# [`\Shef\Haschangefiles\Main`] Как вести правки ядра

Правка ядра — это файл Битрикса, изменённый руками: шаблон компонента, класс
модуля, скрипт. Обновление платформы перезапишет его молча. Модуль не
запрещает и не чинит правки — он помнит, **какие** файлы правили, и после
обновления показывает, какие из них надо вернуть.

Держится всё на двух договорённостях: пометка в коде и зеркало рядом с
файлом.

## 1. Вносим правку с пометкой

Изменения обрамляются блоком `// change ////` … `// change stop ////`, а
прежний код остаётся закомментированным внутри:

```php
<?php
function test(): void
{
	foreach($list as $item)
	{
		// change ////
		// $item['NAME'] = $item['CODE']; ////
		$item['NAME'] = sprintf('[%s] %s', $item['ID'], $item['CODE']);
		// change stop ////
	}
}
```

Маркер ищется подстрокой, варианты — в `\Shef\Haschangefiles\Main\Utils::changeMarkers()`: кроме
`// change` засчитываются `//change` и опечатки `//cahnge`, `// cahnge`,
которые уже разошлись по порталам. Без маркера правка получит состояние
«Нет пометки»: файл и копия совпадают, но найти правку в файле глазами
нельзя.

## 2. Сохраняем зеркало

Файл с правкой копируется рядом под именем `has-change_<имя>`:

```
somecode/test.php
somecode/has-change_test.php     <- копия test.php с правкой
```

Копия — это и есть память модуля: по ней видно, как файл выглядел с
правкой. В PhpStorm оба файла можно выделить и сравнить: контекстное меню
→ **Compare Files**.

## 3. Обновление

Обновление Битрикса перезаписывает `somecode/test.php`, а `has-change_test.php`
не трогает — таких файлов у ядра нет. Теперь они разные:

* `somecode/test.php` — новый код ядра, без правки;
* `somecode/has-change_test.php` — старый код с правкой.

Отчёт **Настройки → Правки ядра → Учёт правок** показывает строку
«Восстановить». Из консоли то же даёт
[`cli/check-core-changes.php`](2_cli.md).

Перед установкой обновлений модуль сам напомнит: на странице
**Обновление платформы** кнопки «Установить обновления» сначала спрашивают,
зафиксированы ли правки, а рядом появляется кнопка «Правки ядра».

## 4. Возвращаем правку

1. Открыть отчёт, найти строку «Восстановить».
2. Ссылка с датой открывает файл в PhpStorm через JetBrains Toolbox. Проект
   по умолчанию — имя сервера; назван иначе или сайт лежит в проекте не в
   корне — укажите в настройках модуля (вкладка «PhpStorm»).
3. Сравнить `test.php` с `has-change_test.php`, перенести правку в новый код.
4. **Снова скопировать** `test.php` в `has-change_test.php`: зеркало
   обязано быть копией файла с правкой, иначе отчёт будет показывать
   расхождение и дальше.
5. Выложить оба файла на сервер. В отчёте — «На месте».

## Состояния

| состояние | в отчёте | что значит |
|---|---|---|
| Status::Ok | На месте | файл совпадает с зеркалом, пометка есть |
| Status::Drift | Восстановить | файл разошёлся с зеркалом — обычно его перезаписало обновление |
| Status::NoMarkers | Нет пометки | совпадают, но в файле нет `// change` |
| Status::NoOriginal | Нет файла | зеркало есть, а файла нет — ядро его удалило или переименовало |

Сравнивается **содержимое**, а не размер: до 2.0.0 сравнивался только размер,
и обновление, заменившее в файле символ на символ, выглядело «правкой на
месте». Решает `\Shef\Haschangefiles\Main\Utils::isSameContent()`, состояние
собирает `\Shef\Haschangefiles\Main\Utils::getStatus()`.

## Где модуль ищет

Отчёт и консольная проверка обходят одно и то же — два раздела
(`\Shef\Haschangefiles\Main\Scanner::getScope()`):

| раздел | где | что пропускается |
|---|---|---|
| Публичная часть | корень сайта | `/bitrix`, `/upload`, `/local`, `/images` |
| Ядро Битрикса | `/bitrix` | `/bitrix/cache`, `managed_cache`, `stack_cache`, `html_pages`, `backup`, `updates`, `tmp` и прочее, где правок не бывает |

Каталоги пропускаются путём, на своём уровне: `/bitrix/cache` — нет, а
`/bitrix/modules/main/lib/cache/` — да, обходится. По имени на любой глубине
пропускается только `.git`
(`\Shef\Haschangefiles\Main\Scanner::DEFAULT_SKIP_NAMES`). По символическим
ссылкам на каталоги обход не ходит: ссылка наверх давала бесконечный обход, а
общий `/bitrix` нескольких сайтов — одни и те же файлы дважды.

`/local` не обходится сознательно: это код проекта, а не ядра, его
обновление не перезаписывает и зеркала ему не нужны.

## Свой отчёт

Всё, что делает страница, доступно классами `\Shef\Haschangefiles\Main\Scanner`
и `\Shef\Haschangefiles\Main\ChangeFile` — и без поднятого ядра:

```php
use Shef\Haschangefiles\Main\ChangeFile;
use Shef\Haschangefiles\Main\Scanner;

foreach(Scanner::find($_SERVER['DOCUMENT_ROOT'].'/bitrix') as $mirror)
{
	$change = new ChangeFile($mirror);
	if($change->isNeedFix())
	{
		echo $change->getStatus()->value, ' ', $change->getOriginalPath(), PHP_EOL;
	}
}
```

`\Shef\Haschangefiles\Main\Report::getRow()` отдаёт строку в формате `main.ui.grid` — с экранированием
и ссылкой в PhpStorm. Запускаемые примеры — [check.php](../examples/check.php)
и [report.php](../examples/report.php).
